# Railway Deployment Plan: mcp-google-server

## 1. Overview
This document outlines the steps required to deploy the `mcp-google-server` to [Railway](https://railway.app). 
Currently, the server uses a `stdio` transport layer, which is ideal for local, direct-process communication. However, Railway is a PaaS that expects applications to listen on an HTTP port. To successfully deploy and communicate with this server remotely, we must add an HTTP/SSE (Server-Sent Events) transport.

## 2. Required Code Changes (Pre-Deployment)
Before pushing to Railway, the server's transport mechanism must be updated to support HTTP/SSE so that remote clients can connect to it over the internet.

1. **Install Express (or a similar web framework)**:
   ```bash
   npm install express
   npm install --save-dev @types/express
   ```
2. **Update `src/server/mcp_server.ts`**:
   Modify the `start()` method to instantiate an Express server and use `SSEServerTransport` instead of `StdioServerTransport`.
   
   *Example implementation:*
   ```typescript
   import express from "express";
   import { SSEServerTransport } from "@modelcontextprotocol/sdk/server/sse.js";

   // Inside your McpGoogleServer start() method:
   public async start(): Promise<void> {
     const app = express();
     let transport: SSEServerTransport;
     
     // Endpoint to establish the SSE connection
     app.get("/sse", async (req, res) => {
       transport = new SSEServerTransport("/message", res);
       await this.server.connect(transport);
     });
     
     // Endpoint to receive messages from the client
     app.post("/message", express.json(), async (req, res) => {
       if (transport) {
         await transport.handlePostMessage(req, res);
       }
     });
     
     const PORT = process.env.PORT || 3000;
     app.listen(PORT, () => {
       console.log(`MCP Server listening for SSE connections on port ${PORT}`);
     });
   }
   ```
3. **Update `Dockerfile`**:
   Railway will automatically assign a `$PORT` environment variable. You don't explicitly need to `EXPOSE` the port in the Dockerfile for Railway, but it's good practice.

## 3. Environment Variables Configuration
Railway uses environment variables for secure configuration. You will need to extract the credentials you generated locally and add them to your Railway project environment.

Gather the following values:
- `GOOGLE_CLIENT_ID`: Your Google OAuth Client ID.
- `GOOGLE_CLIENT_SECRET`: Your Google OAuth Client Secret.
- `GOOGLE_REFRESH_TOKEN`: The refresh token generated by running `npm run auth` locally. (This enables the server to authenticate statelessly on Railway without user interaction).

## 4. Deployment Steps on Railway
1. **Push Code to GitHub**: Ensure all changes (including the SSE transport update) are committed and pushed to your GitHub repository.
2. **Create Railway Project**:
   - Go to the [Railway Dashboard](https://railway.app/dashboard).
   - Click **New Project** > **Deploy from GitHub repo**.
   - Select your repository (`mcp_server_UC`).
3. **Configure Variables**:
   - Go to the **Variables** tab of your new service.
   - Add `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `GOOGLE_REFRESH_TOKEN`.
   - Railway will automatically inject the `PORT` variable.
4. **Trigger Rebuild**:
   - Railway automatically triggers a build using the `Dockerfile` present in the repository root.
   - If the initial build failed due to missing variables, manually trigger a redeploy after adding them.
5. **Generate Public Domain**:
   - Go to the **Settings** tab of your service.
   - Under **Networking**, click **Generate Domain** to get a public `railway.app` URL for your server.

## 5. Connecting to the Deployed Server
Once deployed, remote MCP clients can connect to your server using the SSE URL. 

If your Railway domain is `https://mcp-google-server-production.up.railway.app`, configure your MCP client with the following endpoint:
`https://mcp-google-server-production.up.railway.app/sse`
